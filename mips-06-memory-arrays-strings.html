Begin with bytes, addresses, and registers

Think of memory as a very long sequence of storage locations. Each location holds one byte: eight bits. Each byte location has a number called its address. Consecutive addresses differ by one, so address B+1 means the next byte, not the next integer. An address identifies a location; the bits stored at that location are its contents.

A MIPS word in this course is 32 bits, or four bytes. A word stored in memory therefore occupies four consecutive byte locations. If a word starts at B, its bytes occupy B, B+1, B+2, and B+3. The next consecutive word starts at B+4. The starting address names where the word begins; it is not itself the word’s value.

The CPU’s general-purpose registers, such as $t0, each hold a 32-bit pattern too. They are a separate register file, not four-byte boxes inside your declared memory array. A register can hold an integer, a character code, or a memory address. There is no automatic pointer type: instructions determine how the current bits are used. A load copies memory contents into a register; a store copies register bits into memory. Neither transfer removes the source.

Addresses are often written in hexadecimal, base 16. The prefix 0x announces that notation; digits A through F mean decimal 10 through 15. Each hexadecimal digit represents four bits, so two hex digits describe one byte and eight describe a 32-bit pattern. For example, 0x10 means decimal 16, while 0x10010000 is a complete address—not an array value that must be added into a sum.

Quick check: A word containing 7 begins at B+8. Which quantity locates the word, and which quantity is increased when we add 5 to its loaded value?

Show answer

B+8 locates the word. The loaded value 7 becomes 12 in a register. Memory still contains 7 until a store writes the changed value back.

Where a program’s memory comes from

A program uses addressed memory for both instructions and data. A memory map groups addresses by their intended role. These regions are parts of the program’s address space; they are not extra kinds of registers. The diagram’s fixed numbers describe a particular simulator configuration, not universal physical RAM boundaries. Unused-looking space between drawn regions is not a promise that every intervening address is accessible.

RegionWhat lives there?When is space obtained?Typical lifetime

HeapData whose required storage is requested during executionA runtime allocation requestIn these MARS examples, until the program ends or the simulator is reset
StackTemporary saved values, return destinations, and local storage for active callsCode reserves a frame as needed and later releases itUsually while that call or temporary operation is active

Static does not mean constant. A declared array has storage chosen before execution, but a store can change its elements. A fixed-size input buffer belongs to static data even though its text changes each time input is read. Static storage is declared with directives such as .word and .space inside the .data section; .data selects that section but does not itself allocate an array.

The heap is useful when a program requests an amount of storage while it runs. MARS provides a runtime allocation service, previewed in the worked example below and studied further in the heap lecture; writing .space 128 is instead a static declaration of 128 bytes. The MARS allocation service used in this course has no corresponding free syscall: its allocations last until the program ends or the simulator is reset. Returning from a function does not release heap storage the way its code can release a stack frame. The stack serves a different need: keeping information while functions call other functions. Our stack examples reserve and release space by changing $sp, the stack-pointer register. The usual diagram draws the heap growing toward higher addresses and the stack toward lower addresses. Neither grows automatically just because you write an arithmetic expression.

The text section contains instructions, while the data section contains values to read or change. Both use memory addresses, but their roles differ. A label such as array or main is a symbolic name for an address in the appropriate section. Labels do not enforce array bounds or remember how many bytes were declared. The program must still track lengths and valid addresses.

A 32-bit byte-address pattern can name 2³² possible byte locations mathematically. That does not mean a particular program has 4 GiB of usable memory, or that all those locations are mapped in MARS. Use the simulator’s configured regions and your actual allocations rather than assuming that any representable address is safe.

Under ordinary MARS data-alignment settings, .word declarations are automatically word-aligned. Writing .align 2 explicitly makes the intended boundary and padding clear, especially after byte data. Padding advances the placement address; it does not add initialized array elements.

In these examples, quoted text uses ASCII character codes: H is 72, i is 105, and A is 65. Double quotes delimit the string in the source; the quote marks themselves are not stored. A space inside those quotes is ASCII byte 32, and a # inside them is the character # rather than a comment marker. Negative integers declared with .word use the 32-bit representation already studied. For a byte, the stored eight bits and the later signed or unsigned interpretation are separate questions; we will compare the byte-load instructions below.

An escape sequence writes a special character inside a quoted string. \n represents one newline byte, decimal 10, not a backslash followed by the letter n. \0 represents a zero byte, called NUL. It differs from the character "0", whose ASCII code is 48. Thus .asciiz "Hi\n" stores four bytes: 72, 105, 10, and the automatically appended 0. You do not need to type \0 at the end of an .asciiz string.

An embedded \0 ends a zero-terminated string early even if more declared bytes follow it: .asciiz "A\0B" stores 65, 0, 66, 0. A print-string operation stops at the first zero, so it prints only A. Newline changes the printed line; NUL tells a string-processing operation where the string ends.

Reserve is not the same as initialize. The simulator may show zeros in newly reserved .space storage, but do not treat that observation as the program having established its intended values. Write a byte or word before using it as meaningful data. Before treating a reserved buffer as a string, place a NUL inside it or use an input operation that writes a terminator. Alignment padding is not an extra array element either.

A familiar program skeleton separates those assembly-time declarations from runtime instructions. Here li means load an immediate constant into a register; syscall requests the simulator service selected in $v0. Service 10 exits. The label main names the entry used by our examples; .globl main announces that label to program tools.

Construct an address, load a word, store a word

We now move from declarations to executing instructions. In this independent example, array names the four words 10, −3, 7, 6. From this section onward, B means the array’s own base address. That differs from the earlier declaration walkthrough, where the array began at B+4.

Instruction formMeaning
la destination, labelLoad address: place the label’s address into the destination register. This MARS pseudoinstruction does not read the value stored at the label.
lw destination, offset(base)Load word: read four bytes beginning at base+offset and copy their 32-bit word value into the destination register.
sw source, offset(base)Store word: copy all 32 register bits into four bytes beginning at base+offset. The source register keeps its value.
addiu destination, source, constantAdd the stated integer constant to the source and write a register result. This form does not trap on signed overflow; our small examples stay within range.

Register names begin with $. Commas separate operands. In 8($t0), the parentheses identify the base register, and 8 is an immediate byte displacement. The effective address is the number in $t0 plus 8; the syntax does not mean array element 8 or multiplication by $t0. The displacement is signed and measured in bytes: -4($t0) means the address four bytes before the base, while 4($t0) means four bytes after it. Use either only when the resulting access is valid. Offset 0 selects the byte at the base itself. For a word access, the resulting address must be word-aligned and all four accessed bytes must belong to valid storage.

la    $t0,array       # $t0 receives B, not array[0]
lw    $t1,8($t0)      # read array[2]: its address is B+8
addiu $t1,$t1,5       # change only $t1: 7 becomes 12
sw    $t1,8($t0)      # write 12 back to array[2]

Loading is a copy, and arithmetic on the copy does not update the original. The store is the exact point where memory changes. Also notice the operand direction: lw names its destination first, while sw names the value being stored first. Both put the address expression last.

One program: static data, heap, stack, and registers

Purpose: follow actual values through one complete program and identify their storage locations. We will update a declared integer, request two heap words, save a value and a pointer on the stack, and write a short string into a declared buffer. The same value can exist in several places at once because loads and stores copy bits.

This example is a separate, standalone program. Use a fresh run with MARS’s Default memory configuration and no program arguments. Its first heap request returns the address shown below. Other configurations, extra declarations, earlier allocations, or a different initial stack pointer can change these locations. Let MARS supply the addresses through labels, the allocation result, and $sp; do not hard-code these example addresses into your instructions.

0x marks a hexadecimal number. Addresses below are hexadecimal; ordinary values such as 20, 21, 65, and 99 are decimal. A word occupies four consecutive bytes, and its displayed address is the address of its first byte. These are addresses in the simulated MIPS machine, not file locations on your computer.

2. Heap: request storage while the program runs

li    $a0, 8            # request 8 bytes: room for two words
li    $v0, 9            # select MARS heap-allocation service
syscall                # $v0 receives the new block's address
move  $s0, $v0          # keep that address in $s0
sw    $t1, 0($s0)       # first heap word = 21
li    $t2, 99
sw    $t2, 4($s0)       # second heap word = 99

li loads a literal number into a register. syscall asks MARS to perform the service numbered in $v0. For service 9, $a0 supplies the requested number of bytes, and $v0 receives the allocated block’s starting address. move destination, source copies a register’s bits into another register; it does not write memory. We use $s0 to keep the heap address when later services reuse $v0. The name “saved register” does not automatically place it on the stack.

3. Stack: reserve space, explicitly save, retrieve, then release

addiu $sp, $sp, -8      # reserve 8 bytes by lowering $sp
sw    $t1, 0($sp)       # save the integer value 21
sw    $s0, 4($sp)       # save the heap ADDRESS 0x10040000
li    $t1, 0            # overwrite only the register copy
lw    $t3, 0($sp)       # retrieve the saved integer: 21
lw    $t4, 4($sp)       # retrieve the saved ADDRESS
lw    $t5, 4($t4)       # follow that address to heap word 2: 99
addiu $sp, $sp, 8       # release this stack reservation

$sp is a register holding the current stack pointer. addiu $sp, $sp, -8 subtracts eight from it: 0x7fffeffc − 8 = 0x7fffeff4. This reserves eight bytes by convention but does not copy any values. The following sw instructions perform the saves. We are demonstrating temporary storage in straight-line code here; the function-calling convention is developed in the later stack lecture.

What this shows: a stack word can hold an integer or an address. Saving a pointer does not copy the heap block onto the stack. Restoring $sp releases the reservation without erasing the bytes: they may still be visible in MARS, but our program must treat that area as released and must not rely on its old contents. The heap block remains allocated. MARS service 9 has no matching free service.

4. A buffer’s changing contents still live in static data

la    $t6, buffer       # register receives address 0x10010008
li    $t7, 65           # register receives the ASCII code for A
sb    $t7, 0($t6)       # write one byte: A
sb    $zero, 1($t6)     # write the next byte: NUL

sb source, offset(base) means store byte: copy the lowest eight bits of the source register to one byte at the computed address. Unlike sw, it writes only one byte. $zero always reads as zero. Therefore, the first store writes decimal 65 to 0x10010008; the second writes 0 to 0x10010009. The remaining two reserved bytes are not used by this string.

What this shows: allocation location and current contents are different ideas. Writing into buffer does not turn it into heap storage. The NUL byte makes the two-byte sequence a valid string representing “A”; it stops print-string before the unused part of the buffer.

Find these locations in MARS

  1. Open this file by itself and assemble it using the Default memory configuration. In the Execute view, locate the Text Segment, Data Segment, and Registers displays.
  2. In Data Segment, inspect 0x10010000: the words cover age, the four greeting bytes, and the buffer. MARS commonly displays four bytes together as one word. In the default little-endian view, greeting’s bytes 48 69 0a 00 appear as the word 0x000a6948; read them in increasing byte-address order to recover the string.

When the stack is useful: keep a value across a function call

Purpose: the preceding program showed how to store and retrieve values. This separate program shows a reason to do so: main needs the value 21 after another function reuses the temporary register holding it. Save a copy on the stack before the call, then restore it after the call. This is an introduction to the function and stack topics developed in Lectures 07 and 08.

In the diagram, $t1, $s0, and $sp are all registers inside the CPU. The number in $s0 points to a heap word; the number in $sp points into the stack. Holding an address does not move the register into memory. Both the heap and the stack are regions of the program’s addressed memory.

The helper function is called do_work. A function is a named block of instructions that another part of the program can call and then resume from. Its label names an instruction address in the text section. Here the helper deliberately replaces $t1 with 99 so we can see why its caller protects 21.

Alignment: where a word can start
Alignment determines where an access may start. Memory has a separate address for each byte. A MIPS word contains four bytes, and an ordinary lw or sw in MARS must start at an address divisible by four. Such an address is word-aligned. Endianness, introduced next, answers a different question: which byte of the word belongs at each address.


AccessBytes accessedRequired starting address in MARS
lb, lbu, sb1 byteAny valid byte address.
lh, lhu, sh2 bytes: one halfwordA multiple of 2.
lw, sw4 bytes: one wordA multiple of 4.


The names mean load byte, load byte unsigned, store byte; load halfword, load halfword unsigned, store halfword; and load word, store word. A halfword has 16 bits. The unsigned byte/halfword loads fill the remaining upper register bits with zeros; their signed counterparts copy the loaded sign bit into those positions. These interpretation choices do not change the alignment requirement.


Why does alignment matter? An aligned word fits within a natural four-byte boundary. A word starting one byte later crosses that boundary and needs additional handling. Requiring alignment simplifies ordinary word accesses in the classic MIPS model used here. MARS reports an address error for a misaligned lw or sw; other processors may have different rules and hardware for unaligned accesses.

Endianness determines the order of bytes inside a multibyte value. Lecture 06 uses both whole-word loads/stores and individual-byte loads/stores, so we need to know what a byte instruction sees inside a word. MARS can display four memory bytes together as one hexadecimal word. Seeing 0x12345678 in that word display does not mean the lowest-address byte is 0x12. Endianness does not reverse bits inside a byte: 0x78 still has bits 01111000. It also does not reverse the character sequence in this declaration:

Keep the terminator inside the input buffer
A buffer is allocated storage that can hold data; a string is a sequence of character bytes ending at its first NUL. Capacity counts allocated bytes, while string length counts characters before NUL. For example, .asciiz "cat" stores 99, 97, 116, 0: three characters in four bytes. Newline is code 10; NUL is code 0; the digit character "0" is code 48.
Review the simulator interface before reading input: li places a constant in a register; la places a label’s address there; move destination, source copies a register without changing the source. syscall performs the service chosen in $v0. The $a0 and $a1 registers carry the arguments required by that service; these are not automatically inferred from a declaration.
For read-string service 8, put the destination buffer address in $a0 and its byte capacity in $a1. The following input fragment assumes a declaration buffer: .space 128 has reserved the storage. It selects service 8 and initializes that buffer with input plus a terminating NUL.
li $v0,8             # select read-string service
la $a0,buffer         # address, not current buffer contents
li $a1,128            # capacity includes room for NUL
syscall
With this capacity, the service stores at most 127 input bytes and then a NUL. If the entered line fits with room for its newline, the captured newline is stored before NUL. Entering cat and pressing Enter gives 99, 97, 116, 10, 0. A captured newline is not the end marker expected by print-string service 4; service 4 stops at zero and will print a newline byte it encounters.
Our reversal program replaces a captured newline with zero before swapping characters. We recommend at most 126 ASCII characters so both the newline and final NUL can fit in the 128-byte buffer. Empty input with Enter can initially contain newline then NUL; trimming the newline produces an empty string. If input fills the available character space, do not assume a newline was stored: stop at the NUL or the capacity bound.
Before a scanning loop, read its branch instructions literally: beq r1,r2,label branches when the two register values are equal; MARS also accepts an immediate comparison such as beq $t2,10,trim_newline. beqz register,label tests for zero; bnez tests for nonzero. blt, bgt, and bge are pseudoinstructions for signed less than, greater than, and greater than or equal comparisons. Our nonnegative capacities and ASCII codes have the same ordering in signed and unsigned form; the reversal program uses an explicitly unsigned comparison for pointer addresses. The target is a code label defined with a colon. A j always jumps; a nop does nothing. The zero register $zero always supplies the value 0.
A correct scan checks the object’s boundary as well as its stopping byte. Service 4 is given an address, not a capacity, so it depends on a reachable NUL inside valid storage. The bounded-scan exercise instead tracks both address and capacity explicitly. These examples process ASCII bytes; reversing arbitrary UTF-8 bytes is not a general Unicode character-reversal algorithm.

The code below is the swap body, not a complete loop. On entry, $t0 and $t1 hold valid addresses of the left and right characters. Write MIPS code
Write a fragment that replaces every ASCII digit in a NUL-terminated buffer with #. $t0 points to an allocated buffer of at most 32 bytes containing its terminator. Preserve $t0 and the NUL, use $t1–$t3 as scratch, and leave nondigits unchanged. Test "a1B9!" and "no0"; print nothing.
Reveal solution and trace
move $t1,$t0
mask_loop: lbu $t2,0($t1)
beqz $t2,done
nop
blt $t2,48,advance
nop
bgt $t2,57,advance
nop
li $t3,35
sb $t3,0($t1)
advance: addiu $t1,$t1,1
j mask_loop
nop
done: nop

15. Copy a string including its terminator
Topic: Exit check: bytes, words, and zero
Write MIPS code
Write a fragment to copy a NUL-terminated ASCII string from $t0 to a nonoverlapping destination at $t1. Both allocations have 32 bytes; the source contains a NUL within them. $t0/$t1 may advance, $t2 is scratch, and no output is required. Copy the terminator too. Test "ab" and empty input.
Reveal solution and trace
copy_loop: lbu $t2,0($t0)
sb $t2,0($t1)
addiu $t0,$t0,1
addiu $t1,$t1,1
bnez $t2,copy_loop
nop
