A result is not a return destination

Arithmetic instructions calculate values. Branches and jumps select the next instruction. A function call combines a jump with a record of where execution should resume afterward.

Quick check: A function calculates the integer 44. Can 44 automatically tell the machine which instruction in its caller comes next?

Show answer

No. The computed result and the instruction address are different information. The function places its result in an agreed result register; a separate return address identifies where to resume.

Caller, callee, and leaf

The caller makes a function call; the callee receives it. These names describe a relationship. A function called by main may itself call another function, becoming a callee in one relationship and a caller in another.

A leaf function calls no other function. Today’s polynomial evaluator is a leaf. Entering a label does not automatically create protected local variables or save registers. A label names an instruction address; a working function also needs an agreement about inputs, outputs, and preserved state.

This agreement is a calling convention. The assembler does not check that every programmer follows it, so the convention must be visible in the code and its documentation.

Write the contract first

Our function evaluates a*x*x+b*x+c. The function signature is polyval(x,a,b,c), with x first.

Copy the arguments into these registers before calling. The first four integer/pointer arguments fit the four argument registers in our simplified convention. More elaborate calling conventions handle additional arguments; they are outside today’s example.

State numeric assumptions too. The supplied fixed values are small and all intermediate products fit signed 32-bit range. A register holds bits, so the function’s interface—not an automatic type system—determines how those bits are interpreted.

Learn and work through

Jal calls; jr returns control

li $a0,3
li $a1,3
li $a2,4
li $a3,5
jal polyval
nop
move $t4,$v0

jal records a return destination in $ra and jumps to the named function. The function eventually executes jr $ra, jumping to that saved address. The result is already in $v0; jr does not “return the number.”

Our MARS configuration has delayed branching off, so the return destination is the next sequential instruction. Here that is a harmless nop, followed by the result copy. Classic delayed-branch execution uses a delay slot and a different link calculation. Keep the selected simulator mode consistent rather than mixing the two models.

A leaf can use its incoming $ra directly because it makes no further call to overwrite it. Nested calls will require additional preservation in Lecture 9.

Translate the function body
polyval:
    mul $t0,$a0,$a0       # x*x
    mul $t0,$t0,$a1       # a*x*x
    mul $t1,$a0,$a2       # b*x
    addu $t1,$t1,$a3      # b*x+c
    addu $v0,$t0,$t1      # final answer
    jr $ra
    nop
The function uses two temporary registers as scratch space. It does not change saved registers or the stack pointer, so this leaf requires no stack frame. Its arithmetic is separate from printing: callers can use the result for output, another calculation, or a later function argument.
The full program terminates main before execution can fall into this function body. Labels and indentation do not create execution boundaries. The downloadable example is L07_polyval.asm.

Which registers may change?
RegistersResponsibility
$a0–$a3, $v0–$v1, $t0–$t9Caller-saved: the caller protects values it still needs after the call.
$s0–$s7Callee-preserved: a callee restores any of these that it changes.
$spA returning function restores its incoming stack position.
$raA function protects its incoming return destination before another call overwrites it.
“Caller-saved” does not require saving every temporary before every call. Save live values: values needed afterward. “Callee-preserved” does not prohibit using saved registers; it requires restoring their old values.
Copying a value into another temporary does not protect it from an arbitrary later function. That function may use any temporary under the same convention.
Learn and work through
Printing can overwrite the result
MARS uses $v0 both for a function result and for the service number of a syscall. Selecting print-integer service 1 overwrites whatever result was in $v0.
# Correct when printing immediately:
move $a0,$v0        # copy the answer first
li $v0,1            # then choose the service
syscall
If you load 1 first and then copy $v0, the printed value is 1 instead of 44. When printing a label before the answer, first save the result in a suitable location, then set up the output services. The full program uses $t4 because no further ordinary function is called before the answer is printed.
A syscall service convention and a normal function calling convention are separate agreements even when they reuse the same registers.

Return two related values
The simplified integer convention provides two result registers, $v0 and $v1. Consider a leaf with x in $a0 that returns x² in $v0 and 2x in $v1. A caller must know both meanings; the hardware does not attach labels to the results.
