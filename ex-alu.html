Exercise set 9 · after the ALU lecture Selecting and computing

One box that does everything

The multiplexer and the decoder; building large multiplexers two different ways; and the arithmetic logic unit — one circuit that performs whichever operation its control wires ask for, assembled from the adder of Set 8.

A processor executes a different operation almost every instruction, and it cannot afford a separate machine for each one. What it has instead is an arithmetic logic unit: two operands in, one result out, and a small code on the side saying which function to apply. One piece of hardware, told each cycle what job to do.

Building one needs a component this course has not met yet — a circuit that chooses. That is the multiplexer, and it turns out to be as fundamental as the gates themselves.

9.1The multiplexer

A multiplexer, universally shortened to MUX, is a data selector: several inputs, one output, and a control value that decides which input reaches the output. The smallest one has two data inputs and a single select line.

Notice that the data inputs and the select input play completely different roles even though they are all just wires. A and B are data — the multiplexer does not care what they mean. S is control. That distinction is what makes the device useful, and it is the same distinction as the control input on the XOR-based conditional inverter from Set 4.

9.3Decoders

A decoder takes an n-bit number and raises exactly one of its 2n output lines — the one whose index matches the input. It converts a binary code into a position.

S1S0Y0Y1Y2Y3
001000
010100
100010
110001

Each output is 1 for exactly one input combination, so each output is a minterm of the select inputs — the same minterms as Set 5, now with one AND gate apiece:

A pattern with exactly one 1 in it is called one-hot, and that is what a decoder produces. It is the natural shape for “pick one of these”: one wire per choice, and the wire that is high is the choice.

With one-hot lines available, a multiplexer is easy. AND each data input with its own decoder line — which passes that input through when its line is high and forces 0 otherwise — then OR the results, since at most one of them can be non-zero:

Decoders on their own

Decoders are not only multiplexer parts. Any time a binary code has to turn into “activate exactly this one thing”, a decoder is the circuit: choosing one row of a memory from an address, choosing one register from a register number, or choosing which unit acts on an instruction’s opcode. The MIPS machinery later in the course uses them for all three.

9.4Multiplexers are universal

Set 7 showed NAND alone can build any circuit. The multiplexer can too — which is a surprise, since it looks like a routing component rather than a computing one.

The argument is short. Feed a 2:1 multiplexer constants on its data inputs and a variable on its select:

MUX(S = A,  0→1,  1→0) = A′

so it can invert. Exercise 9.9 gets AND and OR the same way, and with NOT, AND and OR available, Set 5’s sum-of-products construction finishes the job.

More directly: a 2n:1 multiplexer is a truth table. Put the n variables on the select lines and the output column on the data inputs, and the device looks up the answer. That is Exercise 9.10, and it is the cleanest way to see why no function can be out of reach.

9.5A 1-bit ALU

Now the payoff. Compute all the candidate results at once, in parallel, and let a multiplexer pick the one that was asked for. Start with two logical operations:

Both gates always run. The AND gate computes A·B whether or not anyone wants it, and the multiplexer discards it when the operation code says OR. That feels wasteful and is not: the gates are small, they all work simultaneously, and selecting afterwards costs one multiplexer delay rather than the time it would take to decide first and then compute.

9.6Adding and subtracting

Adding arithmetic means adding a third input to the multiplexer — which means a 4:1 — and wiring the full adder from Set 8 into it:

operationwhat the ALU doeswhich MUX input
00A · BD0
01A + BD1
10A + B + CinD2

And subtraction needs no fourth operation at all. Set 8 ended with the observation that A − B is A + B′ + 1: flip every bit of B, and add one. Both halves are already affordable. Put an XOR on the B input, controlled by a line called B invert, and that XOR passes B through when the line is 0 and inverts it when the line is 1 — the conditional inverter of Exercise 4.3. Then feed that same control line into the carry in of the lowest bit, and it supplies the “+1”.

So the subtract path costs one XOR per bit and one wire. There is no subtractor anywhere in a processor; there is an adder and a control line.

9.7From 1 bit to 32

A 32-bit ALU is 32 copies of the 1-bit one, stacked. Bit k gets Ak and Bk and produces Resultk.

Two things are shared across the whole stack and one is not. The operation code goes to every bit, since all 32 bits must do the same thing — and so does B invert. What is not shared is the carry: the carry out of bit k becomes the carry in of bit k + 1, which is the ripple chain of Set 8 running up the stack.

That chain is also the only slow part. The AND, the OR and the multiplexer in each bit are a couple of gate delays, all happening at once across the whole width; the carry has to travel 32 stages. An ALU’s speed is its adder’s speed.

9.8Reference

  • 2:1 MUX. F = S′A + SB. S = 0 selects A.
  • 2n:1 MUX. n select lines, one product term per data input. Build recursively from 2:1s, or from a decoder plus ANDs and an OR.
  • n-to-2n decoder. One output per input combination, exactly one of them 1 — one-hot. Each output is a minterm.
  • Universality. A 2n:1 multiplexer with the variables on its selects and the output column on its data inputs computes any n-variable function.
  • 1-bit ALU. Compute every candidate result in parallel; select with a multiplexer driven by the operation code.
  • Subtraction. B invert = 1 inverts B through an XOR and supplies the carry in of 1, so the adder computes A − B.
  • 32-bit ALU. 32 copies; operation and B invert shared; the carry chains from each bit to the next.

9.9Exercises

Throughout, S = 0 selects the first data input, and S1 is the more significant of two select lines. Where a question says “draw”, a block diagram is enough unless it asks for gates.

Multiplexers

Give the truth table of a 2:1 multiplexer with inputs A, B and select S, and write the expression. Why is the table of a 2:1 multiplexer eight rows when the device has only two data inputs?
SABF
0000
0010
0101
0111
1000
1011
1100
1111

F = S′A + SB

Eight rows because a truth table has one row per combination of all the inputs, and the select line is an input like any other. Three wires in, so 23 = 8 rows. The select is special in what it means, not in how the circuit treats it.

Reading the table in halves makes the behaviour obvious: in the four rows with S = 0 the F column copies the A column and ignores B; in the four rows with S = 1 it copies B and ignores A.

That is also a good check on any multiplexer answer. If F ever disagrees with the selected input, something is wired wrong; if F depends on the unselected input, something is wired very wrong.

Draw a 2:1 multiplexer from AND, OR and NOT gates, and count them. Then say how many gates it costs in pure NAND.

Four gates: one inverter for S′, two ANDs to form the two product terms, and one OR to collect them. S fans out to the inverter and to the lower AND.

The structure is the two-level AND–OR shape of Set 5, which is no accident — S′A + SB is a sum of products, and this is its standard circuit.

In pure NAND, the rule from Exercise 7.13 applies: a k-term sum of products costs k + 1 NAND gates plus one per complemented variable. Here k = 2 and one variable appears complemented, so 2 + 1 + 1 = four NAND gates — the same count, and in real silicon cheaper, for the reasons in Exercise 7.14.

Four gates for a device this useful is the reason multiplexers are everywhere in a processor rather than being saved for special occasions.

Write the expression for a 4:1 multiplexer with data inputs D0 to D3. How many gates does the direct two-level implementation need, and how many inputs does the widest gate have?

One product term per data input, each guarded by the select combination that names it:

F = S1′S0′D0 + S1′S0D1 + S1S0′D2 + S1S0D3

The count. Two inverters for S1′ and S0′, four 3-input ANDs, and one 4-input OR: seven gates, 19 gate inputs.

The widest gate is the OR, with four inputs — one per data input. That is the part that does not scale: a 16:1 multiplexer built this way needs a 16-input OR and sixteen 5-input ANDs, and gates that wide are not available as single parts. Exercise 9.4 shows the usual way round it.

Notice the select terms are exactly the four minterms of S1 and S0, each appearing once. That observation is what makes the decoder construction of Exercise 9.8 work — a decoder produces precisely those four signals.

Build a 4:1 multiplexer out of 2:1 multiplexers. How many do you need, how are the select lines wired, and how many would an 8:1 take?

Three, in two layers. The first layer uses S0 to choose within each pair — one multiplexer picks between D0 and D1, the other between D2 and D3. The second layer uses S1 to choose between those two results.

The select wiring is the part to get right: S0 goes to both multiplexers in the first layer, and S1 goes to the one in the second. The less significant select chooses within groups; the more significant chooses between groups.

Check it on one case. With S1S0 = 10, the first-layer multiplexers pass D0 and D2 respectively (since S0 = 0), and the second layer picks the lower one because S1 = 1, giving D2 — which is right.

An 8:1 takes seven: four in the first layer, two in the second, one in the third. In general a 2n:1 needs 2n − 1 of them, the same count as the chained ANDs of Exercise 3.8 and for the same reason — each 2:1 reduces the number of surviving candidates by one.

The cost compared with the direct build: more gates in total, but no gate wider than the ones a 2:1 already uses. The delay grows as the number of layers, which is n.

A 4:1 multiplexer has its data inputs tied to the constants D0 = 0, D1 = 1, D2 = 1, D3 = 0, and its selects driven by two variables. What function of those variables does it compute?

Work through the four select combinations. With S1S0 = 00 the output is D0 = 0; with 01 it is D1 = 1; with 10 it is 1; with 11 it is 0.

So the output is 1 exactly when the two selects differ:

F = S1 ⊕ S0

The constants on the data inputs are the output column of the truth table, read top to bottom, and the selects are the input columns. The multiplexer is doing a table lookup.

That is the whole of Exercise 9.10 in miniature, and it is worth pausing on: nothing about the multiplexer knows anything about XOR. Wiring four constants in a particular order produced it, and a different four constants would produce a different function — any of the sixteen two-variable functions, one per choice of constants.

Recall from Exercise 5.13 that XOR is the function two-level minimisation cannot shrink, needing five gates as a minimal sum of products. Here it costs a multiplexer and four wires tied high or low.

Decoders

Give the truth table of a 2-to-4 decoder and the expression for each output. What does “one-hot” mean, and how many of the 16 possible output patterns can a decoder actually produce?
S1S0Y0Y1Y2Y3
001000
010100
100010
110001

Each output is the minterm of the two inputs that matches its index:

Y0 = S1′S0′    Y1 = S1′S0    Y2 = S1S0′    Y3 = S1S0

One-hot means exactly one bit of a group is 1 and all the others are 0. A decoder’s outputs are one-hot by construction, since the input matches exactly one index.

Four patterns of the sixteen, not sixteen: 1000, 0100, 0010 and 0001. The other twelve — including all-zeros and all-ones — never appear. That restriction is the point: a circuit downstream can rely on exactly one line being active and needs no arbitration.

The cost of one-hot is width. Representing one of 32 registers takes 5 bits as a binary code but 32 wires one-hot, which is why codes are used to carry the choice and decoders turn them into one-hot only at the point of use.

Draw a 3-to-8 decoder at the gate level. How many gates, how many inputs does each have, and how many outputs are 1 at any moment?

Eight outputs, each a minterm of the three inputs, so eight 3-input AND gates plus three inverters to make S2′, S1′ and S0′. Eleven gates, 27 gate inputs.

The wiring follows the index in binary: output Y5 is 1 for input 101, so its AND gate takes S2, S1′, S0. Writing the index in binary and reading a plain literal for each 1 and a complemented one for each 0 is the whole construction — and it is the same rule as building a minterm in Set 5.

The 2-to-4 version shows the shape, with one AND per output and the literals chosen by the index:

Exactly one output is 1 at any moment, always. The inputs form some 3-bit number, that number names one output, and no other AND gate can have all three of its inputs high at the same time — any other gate differs from this one in at least one literal.

Note how the cost grows: an n-to-2n decoder needs 2n gates. A 5-to-32 decoder is 32 gates, which is fine; a 32-bit address decoder would need four billion, which is why real memories decode in stages rather than all at once.

Build a 4:1 multiplexer from a 2-to-4 decoder, some AND gates and an OR gate. Explain why an OR is safe here, and compare the cost with Exercise 9.4.

The decoder turns S1S0 into four one-hot lines. Each line is ANDed with its own data input, so that AND gate outputs Dk when its line is high and 0 when it is low. The OR then collects the four results.

Why the OR is safe. Because the decoder output is one-hot, at most one AND gate can be passing anything through; the other three are outputting 0 whatever their data inputs are doing. OR-ing a value with three zeros returns the value. There is never a case where two inputs compete and the OR has to merge them — the same mutual-exclusion argument as the two carries in Exercise 8.6.

The cost. The decoder is 2 inverters and four 2-input ANDs; then four more ANDs and a 4-input OR — eleven gates, against three 2:1 multiplexers (twelve gates) for the recursive build. Comparable, and the real difference is in shape: this version has a constant delay of three gates regardless of size, but needs an OR as wide as the number of inputs, while the recursive version keeps every gate narrow and pays with depth.

Expanding the decoder version gives S1′S0′D0 + … — exactly the expression from Exercise 9.3. The decoder is simply a tidy way of generating the four select terms once.

Multiplexers as computers

Using 2:1 multiplexers and the constants 0 and 1, build NOT, AND and OR. What does this prove?

Each one is a single multiplexer with the right things wired to its inputs.

NOT A — put A on the select, 1 on the first data input and 0 on the second. When A = 0 the output is the first input, 1; when A = 1 it is 0.

A′ = MUX(S = A;  D0 = 1,  D1 = 0)

A · B — put A on the select, 0 on the first input and B on the second. When A is 0 the output is 0, which is right; when A is 1 the output is B, also right.

AB = MUX(S = A;  D0 = 0,  D1 = B)

A + B — put A on the select, B on the first input and 1 on the second. When A is 0 the output is B; when A is 1 the output is 1.

A + B = MUX(S = A;  D0 = B,  D1 = 1)

Each is the function split into its two cases by the value of A — what the algebra calls Shannon expansion, and what the multiplexer does for free.

What it proves. Set 5 showed AND, OR and NOT build every function; these three constructions build AND, OR and NOT; so a 2:1 multiplexer with constants builds every function. The multiplexer is universal, exactly as NAND and NOR are in Set 7.

One caveat worth naming, the same one as in Exercise 7.15: the constants are doing real work. A multiplexer with no access to 0 and 1 cannot invert, because with all its inputs equal to some value the output is that value too.

Show how to implement any function of two variables on a single 4:1 multiplexer. Then say how many data inputs a function of five variables would need, and why that approach does not scale.

Put the two variables on the select lines and the output column of the truth table on the data inputs, in order: D0 gets the output for input 00, D1 for 01, D2 for 10, D3 for 11.

When the variables take some combination, the multiplexer selects exactly the data input holding that row’s answer. The device is performing a table lookup, and the table is the wiring.

Exercise 9.5 was one instance — constants 0, 1, 1, 0 gave XOR, because that is XOR’s output column. Each of the sixteen two-variable functions corresponds to one of the sixteen ways of tying four wires high or low.

Five variables would need a 32:1 multiplexer — 25 data inputs, one per row of the table.

Why it does not scale. The size is 2n, so it doubles with every variable. A 10-variable function would need 1024 data inputs, and the count of distinct functions it could express is the same 22n from Exercise 5.15 — the method is storing the entire truth table, so it inherits the truth table’s size.

What makes minimisation worth doing is exactly this: a Karnaugh map finds the structure in a function and produces a circuit proportional to its complexity rather than to 2n. The multiplexer lookup is the brute-force baseline that always works and is almost never the cheapest.

If the output is the same for both values of C, the data input is that constant. If it follows C, the data input is C; if it is the opposite of C, the data input is C′.

The idea generalises — allow arbitrary functions of the remaining variables on the data inputs and the multiplexer shrinks further — but then you are back to building those functions, and the saving stops being free.

The ALU

Draw a 1-bit ALU that can compute A·B and A + B, selected by one control line. How many gates, and what is the AND gate doing when the control line asks for OR?

An AND gate and an OR gate, both fed the same two operands, with a 2:1 multiplexer choosing which result leaves. Six gates in all — the two operation gates plus the four that make up the multiplexer.

The AND gate is still computing A·B, exactly as it always does. Its output simply goes nowhere: the multiplexer ignores that input and passes the OR result instead.

This is the design idea the whole ALU rests on, and it is worth being explicit about because it looks wrong at first. The circuit computes every operation on every cycle and throws away all but one result.

The reason it is right: gates work in parallel and cost almost nothing, while deciding costs time. An alternative that somehow switched the operands into only the needed gate would have to make the decision first and then compute, which is slower and needs extra circuitry to do the switching — circuitry that would itself be multiplexers. Computing everything and selecting is both simpler and faster.

It does cost power, which is why modern processors go to some lengths to stop unused blocks from switching. But at the scale of one ALU it is the right trade and has been since the beginning.

Extend the ALU so it can also add. What size multiplexer is needed, what goes on each data input, and what are the operation codes?

Three operations need three multiplexer inputs, and multiplexers come in powers of two, so a 4:1 is used with one input spare.

operationwhat the ALU doeswhich MUX input
00A · BD0
01A + BD1
10A + B + CinD2

The fourth input, selected by code 11, is unused — tie it to 0, or use it for a fourth operation when one is needed. Real designs fill it: the MIPS ALU of the textbook uses the spare slot for the comparison that implements slt.

What the full adder needs that the logic gates do not is a carry in and a carry out. The carry in comes from the bit below and the carry out goes to the bit above, so the arithmetic input is the only one connected to its neighbours — which is what makes the width of an ALU matter at all.

Note that the adder also runs on every cycle, including when the operation is AND. Its result is discarded, and its carry out is produced and propagated regardless. That costs nothing extra in time, since the carry chain is doing its rippling while the logic gates idle.

The ALU subtracts without a subtractor: an XOR on the B input and a control line called B invert. Explain exactly how A − B comes out, and say what that control line must also be connected to.

The XOR is a conditional inverter, from Exercise 4.3. With B invert = 0 the XOR passes B unchanged, so the ALU behaves exactly as before. With B invert = 1 it passes B′, so the adder receives A and B′ instead of A and B.

What the adder then computes is A + B′ + Cin. From Set 8, the two’s complement of B is B′ + 1, so what is wanted is A + B′ + 1 — which is the same expression with Cin = 1.

So B invert must also drive the carry in of the lowest bit. That is the second connection, and it is the whole of the “add one”. One control line does both jobs: it flips the bits and supplies the extra 1, which is exactly the two-part negation rule.

The cost of being able to subtract is therefore one XOR gate per bit plus a wire to the bottom carry in. No second adder, no borrow logic, nothing that scales with how often subtraction is used.

And the carry out of the top bit is discarded, exactly as Exercise 8.16 explained. The ALU does not need to know whether it is adding or subtracting — it adds in both cases, and the control line changes what it is adding.

For the 1-bit ALU above, give the Result when A = 1, B = 0, carry in = 1 and the operation code is 00, then 01, then 10. Which of these depends on the carry in?

Take B invert = 0, so the adder sees B itself.

operationwhat it computesResult
00A · B = 1 · 00
01A + B = 1 + 01
10A ⊕ B ⊕ Cin = 1 ⊕ 0 ⊕ 10

Code 00, AND: 1·0 = 0.

Code 01, OR: 1 + 0 = 1.

Code 10, add: 1 ⊕ 0 ⊕ 1 = 0, with a carry out of 1 — the column total is 2, so the sum bit is 0 and the 2 is carried.

Only the add depends on the carry in. The AND and OR gates take only A and B; nothing from the neighbouring bit reaches them. That is why logical operations on a 32-bit ALU complete in a couple of gate delays while arithmetic waits for the ripple.

It is also why the carry out is meaningless after a logical operation. The adder produced one, because it runs regardless, but it describes an addition nobody asked for. A processor's flags are only updated from the carry out when the instruction was an arithmetic one.

A 32-bit ALU is built from 32 copies of the 1-bit one. Which signals are shared across all 32 copies and which are not? How long does a 32-bit AND take compared with a 32-bit add?

Shared by all 32 bits: the operation code, since every bit must perform the same operation, and the B invert line, since a subtraction inverts the whole of B rather than part of it. Both are broadcast.

Not shared: the data. Bit k gets its own Ak, Bk and produces its own Resultk.

And chained rather than shared: the carry. The carry out of bit k is the carry in of bit k + 1, so the bits are not quite independent — a thin thread of dependency runs up the stack.

The timing. A 32-bit AND takes the delay of one AND gate plus one multiplexer — perhaps three gate delays — and all 32 bits do it simultaneously, so the width costs nothing at all.

A 32-bit add takes about 64 gate delays, by Exercise 8.8, because the carry has to ripple through every stage before the top bits are correct. The width costs everything.

Same hardware, same cycle, twenty-fold difference in time — and since the clock must be slow enough for the worst case, the adder sets the clock period and the logical operations finish early and wait. That imbalance is why carry-lookahead (Exercise 8.18) is worth its considerable extra area.

Why is the multiplexer placed inside each 1-bit ALU, rather than building three separate 32-bit units — an AND unit, an OR unit and an adder — and selecting between their outputs with one 32-bit-wide multiplexer at the end?

Start by noticing the two designs compute the same thing and cost nearly the same in gates. The separate-units version needs 32 ANDs, 32 ORs and a 32-bit adder — the same operation gates as before — plus 32 multiplexers at the end to choose among the three results. The per-bit version needs the same gates and the same 32 multiplexers. The multiplexers moved; they did not multiply.

So the answer is not gate count. It is everything else:

  • Layout and wiring. The per-bit version is one small cell repeated 32 times, with short wires inside each cell and only the carry crossing between neighbours. The separate-unit version sends every intermediate result across the chip to a multiplexer bank, which is 96 wires of 32 bits spanning the whole unit. On a chip, wires cost area and delay, and a design that keeps signals local wins.
  • Regularity. One cell designed, verified and laid out once, then tiled. That is how real ALUs are built, and it is why the 1-bit ALU is the unit of design in the first place.
  • Extensibility. Adding a fourth operation means widening one multiplexer in one cell and re-tiling. In the other design it means a whole new 32-bit unit.

The delay is the same either way, since one multiplexer sits between the operation gates and the output in both.

The general lesson is one worth carrying into the MIPS chapters: at this scale, designs are judged on regularity and wire length as much as on gate count, and “build one bit well and repeat it” is the dominant style.

Challenge. Exercise 9.9 built NOT, AND and OR from 2:1 multiplexers with constants. Show that the constants are essential: prove that a circuit built only from 2:1 multiplexers, with its data and select inputs taken from the variables alone, can never compute A′.

The argument is the one from Exercise 3.15 and Exercise 7.15, applied to a new component: find a property that every circuit of this kind preserves, and show the target function does not have it.

The property. Set every variable to 0 and consider any multiplexer whose three inputs all carry 0. Its output is one of its data inputs — whichever the select picks — and both of them are 0, so its output is 0 as well, whatever the select is doing.

Propagating it. Order the multiplexers so that each comes after the ones feeding it, which is always possible in a circuit without loops. The variables all carry 0 by assumption; so the first multiplexer outputs 0; so every wire feeding the second carries 0, and it outputs 0; and so on to the output of the circuit.

So any such circuit outputs 0 when all its inputs are 0. But A′ must be 1 when A is 0. No circuit of this kind computes it.

The same argument with every variable set to 1 shows the circuit must output 1 on the all-ones input, so the constant functions are unreachable too.

What the constants add. A tied-high input is a source of 1 that does not depend on the variables, which breaks the property immediately — and Exercise 9.9 shows that one such input is all it takes to reach everything.

The pattern behind all three

Exercise 3.15 ruled out AND and OR without NOT; Exercise 7.15 narrowed sixteen candidate gates to NAND and NOR; this rules out multiplexers without constants. All three are the same proof: a circuit made of parts that preserve some property can only ever compute functions with that property. The property here is “0-preserving”, and it is the first of the five conditions in Post’s theorem mentioned in Set 7.

Which is why universality claims always come with small print. NAND is universal on its own; multiplexers are universal given constants; and whether the constants count as free depends on whether your technology hands you a power rail — which, conveniently, it always does.

Storage needs feedback, and feedback is where the second half of the course begins; after that, the instructions that drive these control lines, which is MIPS.
