Control flow: choosing what runs next

So far, instructions have executed in order. A decision changes that path. The program counter (PC) identifies the instruction address; a branch or jump can select another address. A label gives that destination a readable name.

Use a “human compiler” process: write a precise high-level condition, sketch the possible paths, choose registers, then translate the paths into instructions. Indentation and blank lines help readers, but they do not create executable blocks. Only the actual control-transfer instructions determine which statements run.

Learn and work through

Comparing is different from branching

slt $t1, $t0, $t2

This instruction sets $t1 to 1 if signed $t0 is less than signed $t2, otherwise 0. It produces a Boolean flag but does not jump. slti compares a register with a signed immediate.

beq $t1, $zero, done
bne $t1, $zero, body

beq branches if two register values are equal; bne branches if they differ. These compare values and choose control flow without creating a result flag. If a branch is not taken, execution falls through to the next instruction in the no-delay mode used here. j label is unconditional.

Signed slt treats 0xffffffff as −1; unsigned sltu treats it as 4294967295. Equality compares the same bit patterns either way.

Worked example: one conditional action

Suppose x is in $t0 and the body should run only when x>0. Testing 0<x expresses the same condition using slt.

slt $t1, $zero, $t0
beq $t1, $zero, end_if
nop
# body instructions
end_if:
# next statement

The branch skips the body when the flag is zero. Its destination means “the conditional action is finished,” so branching there requires the condition to be false. For x=5 the body runs; for x=0 or −5 it is skipped.

nop performs no useful data operation. These examples include it after control transfers, but the required MARS setting remains delayed branching OFF. A label executes nothing by itself.

An if/else needs a way past the other arm

slt $t1, $zero, $t0
beq $t1, $zero, nonpositive
nop
li $t2, 1
j done
nop
nonpositive:
    li $t2, 0
done:

This sets $t2 to 1 for a positive x and 0 otherwise. The conditional branch selects the nonpositive arm. The unconditional jump prevents the positive arm from falling into the other arm afterward.

Without j done, positive input would first set $t2=1 and then overwrite it with 0. A label is not a wall. A correct if/else structure must ensure that exactly the intended arm executes before both paths join.

Notice the word nonpositive: zero belongs to the x≤0 case. Calling that whole case “negative” would misclassify zero.

Three requirements: positive, small, and even
Accept x exactly when x>0 AND x<10 AND x%2==0. An AND chain fails as soon as one requirement fails. Branch to rejection immediately after a failed test:
slt $t1, $zero, $t0
beq $t1, $zero, rejected
nop
slti $t1, $t0, 10
beq $t1, $zero, rejected
nop
andi $t1, $t0, 1
bne $t1, $zero, rejected
nop
# accepted
For x=2, the first two flags are 1 and the low-bit value is 0, so all rejection branches are avoided. For x=3, the last test rejects. Zero fails the first test; 10 fails the second. Exactly 2,4,6,8 are accepted by the complete program.
The remainder itself is not an “is even” flag: an even value has remainder zero. To obtain a true flag for evenness, compare the remainder with zero; alternatively, branch away when the low bit is nonzero, as above.
Learn and work through
AND, OR, and short-circuit evaluation
AND: every requirement must succeed, so any failure can go directly to rejection. OR: one success is enough, so any success can go directly to acceptance. This is short-circuit evaluation: later tests need not run when the result is already known.
For x<0 OR x>100, accept when the first comparison succeeds. Otherwise test the second, and accept if it succeeds. Reject only after both fail. Sketching the destinations makes the logic clearer than trying to memorize branch patterns.
Bitwise AND can combine already-normalized 0/1 flags. It cannot safely substitute for logical AND on arbitrary integers: 2 AND 4 is zero even though both values are nonzero.

Worked example: a half-open interval
Accept x exactly when 10≤x<20. Reject values below 10, then reject values that are not below 20.
slti $t1, $t0, 10
bne $t1, $zero, reject
nop
slti $t1, $t0, 20
beq $t1, $zero, reject
nop
# accepted
The first branch uses bne because a true “below 10” flag means failure. The second uses beq because a false “below 20” flag means failure. The branch operation follows the meaning of its destination. Test 9,10,19,20: the middle two pass, and the endpoints outside the permitted interval fail.

Learn and work through
Branch displacement
A basic branch encodes a signed 16-bit displacement in instruction words. If B is the branch instruction's address and T is the target address:
offset = (T - (B + 4)) / 4
target = B + 4 + 4 * sign_extend(offset)
At B=0x00400020 with T=0x00400030, the offset is (0x30−0x24)/4=3. The reference is the address after the branch, not the branch's own address. Four-byte instructions explain the scaling.
Labels allow the assembler to calculate this. Count assembled instructions when checking manually: pseudo-instruction expansion and explicit nops can make source-line counting incorrect.
Learn and work through
Convenient comparisons and jumps
MARS accepts pseudo-instructions such as beqz $t0,L, equivalent to beq $t0,$zero,L, and sgt, which can reverse slt's operands. Inspect the Basic column to see an actual expansion.
For ordinary control flow, j jumps without recording a return address. Later, jal will both record a return address and transfer control for a function call; jr can jump to the address in a register. A normal if/else does not need a function call. Keep the purpose of the transfer separate from the appearance of a shared label.
