A loop has four jobs

A loop needs initialization, a test, a body, and an update. The test decides whether another body execution is allowed. The update must happen on every intended iteration, including iterations that skip printing.

Quick check: Starting with i=1, repeat while i≤4, then increment i. How many times does the body execute, and what is i when the loop stops?

Show answer

Four executions use i=1,2,3,4. The final failed test occurs with i=5. Counting tests instead of body executions gives an off-by-one error.

One outer loop, one inner loop

Calculate 1¹+2²+3³+…+Nᴺ. The outer loop chooses the next base i. The inner loop multiplies i by itself i times. There is no exponentiation instruction hidden in this notation; the ^ operator in C/C++ means bitwise XOR, not exponentiation.

Before each term, set term=1 and j=0. Repeatedly multiply term by i and increment j. When j reaches i, add the completed term to total. Only then advance the outer counter.

total = 0
for i = 1 through N:
    term = 1
    for j = 0 through i-1:
        term = term * i
    total = total + term

Keep each register’s job stable

RegisterMeaningInitialization
$t0N, the fixed limitRead once
$t1i, outer counter1
$t2total0, once
$t3j, completed multiplications0, for every term
$t4term1, for every term

The total starts at zero because zero is the additive identity. A product starts at one because one is the multiplicative identity. Starting term at zero would make every product zero.

An invariant is a statement that stays true whenever execution reaches a particular test. At the inner test, term equals i raised to the number of completed multiplications j. At the outer test, total contains exactly the terms already completed.

Worked example: Nᴺ+N!
This calculation needs two products but only one loop. Set power=1 and factorial=1. For i from 1 through N, multiply power by the fixed N and factorial by the changing i.
mul $t2,$t2,$t0       # power *= N
mul $t3,$t3,$t1       # factorial *= i
addiu $t1,$t1,1
For N=4, the product pairs are (4,1), (16,2), (64,6), and (256,24). Their final sum is 280. Do not confuse this with the previous self-power sum, which was 288.
Both supplied power programs restrict N to 1–9. Although 9’s results fit a signed 32-bit integer, 10¹⁰ does not. A multiply may retain only low product bits; a final printed integer is not proof that no overflow occurred. Zero is excluded to avoid silently choosing a meaning for 0⁰.

OR: one successful condition is enough
Select positive integers satisfying i%7==0 || i%10==6. The second condition means “ends in 6.” A remainder of zero means divisibility.
rem $t2,$t1,7
beq $t2,$zero,print
rem $t2,$t1,10
beq $t2,6,print
j advance
Both successful paths lead to one shared print block. The integer 56 meets both conditions and must appear only once. For N=31, the output is 6 7 14 16 21 26 28. After printing or rejecting a number, execution reaches the shared counter update.

AND: every requirement must hold
This filter requires divisibility by 2 and 3, but not by 4. Reject a candidate as soon as any requirement fails. Print only after all checks pass.
rem $t2,$t1,2
bne $t2,$zero,advance
rem $t2,$t1,3
bne $t2,$zero,advance
rem $t2,$t1,4
beq $t2,$zero,advance
# All three requirements passed: print here.
For N=31, the answer is 6 18 30. Twelve is divisible by 2 and 3 but is rejected because it is divisible by 4. The loop still increments when a number is rejected; otherwise it may test that same number forever.

Alternating signs from parity
Compute 1²−2²+3²−4²+…. Square the current i once. Add its square when i is odd and subtract when i is even. The low bit identifies parity for these positive integers:
mul $t3,$t1,$t1
andi $t4,$t1,1
beq $t4,$zero,even
addu $t2,$t2,$t3
j advance
even: subu $t2,$t2,$t3
For N=4, partial sums are 1, −3, 6, −10. There is no need to calculate a power of −1. The program accepts 1–46,340 so that each individual square fits signed 32-bit range, even though cancellation can make the final result smaller.

Exit check: state and safe arithmetic
Nested loops require separate counters and carefully placed initializations. OR succeeds when any condition succeeds; AND fails when any required condition fails. A correct formula still needs safe intermediate values.

Pythagorean triples
Find all positive ordered triples with a,b,c≤N and a²+b²=c². Three nested loops enumerate all candidates:
for a = 1 through N:
    for b = 1 through N:
        for c = 1 through N:
            if a*a + b*b == c*c:
                print a,b,c
Reset b for every new a, and reset c for every new b. With N=5, (3,4,5) and (4,3,5) both appear. Requiring b≥a would remove mirror pairs and change the requested output. Use N≤100 for this classroom exercise: products fit safely and the search remains reasonably bounded.
Check: How many candidates are tested for N=10, and which triples print?
Show answer
The three independent loops test 10³=1000 candidates. The outputs are (3,4,5), (4,3,5), (6,8,10), and (8,6,10).

A loop computes each i² as a signed 32-bit mathematical value before adding or subtracting it. A proposed input permits i=50,000. Is a small final sum sufficient evidence of correctness? Give the exact intermediate and the signed maximum.
Check your reasoning
No. The intermediate square is 2,500,000,000, exceeding 2,147,483,647. Later cancellation cannot make that earlier signed computation valid.

12. Count ordered Pythagorean triples
Topic: Pythagorean triples
Write MIPS code
Write a three-loop fragment for $t0=N, 1≤N≤20. Check every ordered candidate (a,b,c) with 1≤a,b,c≤N and leave the number satisfying a²+b²=c² in $t6. Use $t1/$t2/$t3 for a/b/c and $t4/$t5 as scratch. Preserve N. Return code and test N=4 and N=5; mirror pairs must both count.
Reveal solution and trace
li $t6,0
li $t1,1
outer_a: li $t2,1
outer_b: li $t3,1
check_c: mul $t4,$t1,$t1
mul $t5,$t2,$t2
addu $t4,$t4,$t5
mul $t5,$t3,$t3
bne $t4,$t5,advance_c
nop
addiu $t6,$t6,1
advance_c: addiu $t3,$t3,1
ble $t3,$t0,check_c
nop
addiu $t2,$t2,1
ble $t2,$t0,outer_b
nop
addiu $t1,$t1,1
ble $t1,$t0,outer_a
nop
Reset b for every a and c for every pair (a,b). This counts the requested ordered solutions without printing each triple.
