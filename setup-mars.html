Installing MARS

MARS is the MIPS simulator we use for the whole assembly-language half of the course: assemble a program, run it one instruction at a time, and watch the registers and memory change as it goes. It is a single Java file, so there is nothing to install — which makes it both the easiest and the most confusing of the two tools, because there is no installer to double-click.

B.1Which program

Search for "MIPS simulator" and you will find two. We use MARS.

MARSSPIM / QtSPIM
written byPete Sanderson & Ken Vollmar, Missouri StateJames Larus
what it isa Java program — one .jar filea native application, one installer per platform
use in this courseyesno

The two accept almost the same assembly language, so a program written for one usually runs on the other. They differ in the parts you will actually be looking at: the register display, the memory viewer, the single-step controls and the set of system calls. Lectures, examples and anything handed out assume MARS, so install MARS even if you already have QtSPIM from another course.

MARS has two homes

The original project page is hosted by Missouri State, and one of the two original authors keeps a maintained build on GitHub. Either is fine — the maintained one simply runs more happily on current versions of Java. Both are linked in §B.3.

B.2Java first

MARS is written in Java and is distributed as a .jar, which is a program that only runs if Java is already on your machine. So Java comes first.

Open a terminal (macOS, Linux) or Command Prompt (Windows) and type:

java -version

Two things can happen.

what you seewhat to do
a version number — almost any version numbernothing. You are ready, and you can go straight to §B.3
command not found, or 'java' is not recognizedinstall Java, below

MARS asks very little of Java. It is an old program and runs on Java 8 or anything newer, so if your machine already has a Java on it at all — and most do, once you have installed anything written in it — you are almost certainly done here. Upgrading a working Java buys you nothing.

If you have none, download the Temurin JDK for your operating system from adoptium.net/temurin/releases and run the installer with its default options. Take the most recent version offered; there is no reason to hunt for an old one. Close and reopen your terminal afterwards, then run java -version again — a terminal that was already open will not see a newly installed Java.

B.3Getting the file

Download MARS from either of these:

computerscience.missouristate.edu/mars-mips-simulator.htm
dpetersanderson.github.io

What you want in both cases is the single .jar file — the download link is usually the version number itself, and the file that arrives will be called something like Mars.jar with a version in the name. There is no installer, no .dmg and no .msi; that one file is the program.

Put it somewhere permanent before you run it. Make a folder you will keep — Documents/CSCI240/ is a good choice — and move the .jar into it. Running it out of your Downloads folder works right up until the day you tidy your Downloads folder.

Download from these two places only

"MIPS simulator download" turns up sites that wrap the jar in an installer of their own. You do not want what they are adding. The two links above are the project itself.

B.4macOS

The reliable way to start MARS on a Mac is from the Terminal. Open Terminal, change to the folder you put the jar in, and run it:

cd ~/Documents/CSCI240
java -jar Mars.jar

Use the real filename — it will have a version number in it. The easy way to get it exactly right: type java -jar (with the trailing space), then drag the jar from the Finder into the Terminal window, which pastes its full path for you, and press Return.

Double-clicking often does not work

Depending on what else is installed, double-clicking a .jar on macOS may do nothing at all, or may unpack it into a folder of files with Archive Utility. Neither means the download is broken. macOS may also refuse it outright with "Mars.jar cannot be opened because it is from an unidentified developer", or call it damaged.

The fix, once: in Terminal, in the folder with the jar, run

xattr -d com.apple.quarantine Mars.jar

That removes the "downloaded from the internet" flag macOS attached to the file. Then Control-click the jar in the Finder, choose Open With → Jar Launcher, and from then on a double-click will start it.

If you would rather not bother, the java -jar command above works without any of this.

A one-click launcher, if you want one

Typing the command every time gets old. Make a file called mars.command next to the jar containing these two lines:

#!/bin/sh
cd "$(dirname "$0")" && java -jar Mars.jar

then make it runnable, once:

chmod +x mars.command

Double-clicking mars.command now opens a Terminal window and starts MARS. Leave that window open while you work; closing it quits the simulator.

B.5Windows

On Windows a double-click usually just works, because installing the JDK normally registers .jar files with Java. Try it first.

If double-clicking opens WinRAR, 7-Zip or File Explorer instead, the association has been taken by an archiver — a .jar really is a zip file, so they are not wrong, just unhelpful. Two ways out:

  1. Run it from the command line. Open Command Prompt, then 
    cd %USERPROFILE%\Documents\CSCI240
java -jar Mars.jar
  2. Fix the association. Right-click the jar → Open with → Choose another app → Look for another app on this PC, and point it at javaw.exe inside your Java installation (it is in the bin folder, typically under C:\Program Files\Eclipse Adoptium\jdk-21…\bin\). Tick Always use this app.
A shortcut that always works

Make a file called mars.bat next to the jar with one line in it:

java -jar Mars.jar

Double-click that instead. If the window flashes and vanishes, add pause as a second line and run it again — the error message will stay on screen long enough to read.

Windows SmartScreen may object to the download before you get this far. Click More info, then Run anyway; in the browser's download list, Keep, then Keep anyway. It objects because an academic project does not buy a commercial signing certificate, not because it has found anything wrong with the file.

B.6Linux and Chromebooks

Install a JDK from your package manager, then run the jar:

# Debian, Ubuntu, Mint
sudo apt install default-jdk

# Fedora, RHEL, CentOS
sudo dnf install java-latest-openjdk

# then, in the folder with the file
java -jar Mars.jar

A Chromebook needs the Linux development environment switched on first: Settings → About ChromeOS → Developers → Linux development environment, then turn it on and accept the defaults. It installs a Debian container and gives you a Terminal app. After that, treat the machine as Debian and use the commands above.

To get it into your applications menu, create a desktop entry. The file goes here:

~/.local/share/applications/mars.desktop

and contains:

[Desktop Entry]
Type=Application
Name=MARS
Exec=java -jar /home/YOURNAME/CSCI240/Mars.jar
Terminal=false
Categories=Development;

B.7Four settings to check

Open the Settings menu once, before you write anything, and make sure these four are as described. The wording moves around slightly between versions, so match the sense rather than the exact words. The defaults are usually right — this is a thirty-second check that saves an hour of confusion later.

settingwantwhy
Delayed branchingoffWith it on, the instruction after a branch executes even when the branch is taken. Real MIPS hardware does this; everything in our lectures assumes it does not. This is the setting most likely to make a correct program behave bizarrely.
Permit extended (pseudo) instructionsonLets you write li, la, move and blt, which the assembler expands into real instructions. We use them from the first program onwards.
Initialize program counter to global mainonStarts execution at the label main rather than at the first instruction in the file, so your .data section can sit wherever you like.
Assemble all files in directoryoffWith it on, MARS tries to assemble every .asm in the folder at once and reports errors from files you are not working on.

B.8Check it works

Do this now, not the night before the first assembly program is due. Five minutes.

  1. Start MARS. You get a window with an Edit tab and an Execute tab across the top, a large panel of registers down the right, and a message area at the bottom.
  2. On the Edit tab, choose File → New and type the program below. Type it rather than pasting it — you want to see what the editor does with the tabs and the comments.
        .text
main:   li      $t0, 6
        li      $t1, 7
        add     $t2, $t0, $t1       # $t2 should end up holding 13

        li      $v0, 4              # service 4: print a string
        la      $a0, msg
        syscall

        li      $v0, 1              # service 1: print an integer
        move    $a0, $t2
        syscall

        li      $v0, 10             # service 10: stop
        syscall

        .data
msg:    .asciiz "MARS is working: 6 + 7 = "
  1. Save it as check.asm, in the folder with the jar. The .asm extension matters — MARS will not assemble a file without it.
  2. Assemble it: Run → Assemble, or F3. The bottom panel should say the assemble succeeded, and the window should switch to the Execute tab showing your instructions laid out with their addresses and machine code.
  3. Run it: Run → Go, or F5. In the Run I/O box at the bottom you should see
MARS is working: 6 + 7 = 13
  1. Now the part worth the five minutes. Choose Run → Reset (F12), then step through one instruction at a time with Run → Step (F7), watching the register panel on the right. After the third step, $t2 turns from 0 to 13 and the value is highlighted. That highlight — one register changing per instruction — is the whole reason we use a simulator instead of real hardware.

If you saw 13 in the output and 13 in $t2, you are set up. Keep check.asm: when something stops working later in the semester, running it again tells you in ten seconds whether the problem is MARS or your program.

What you just wrote

Nothing here needs to make sense yet. Lecture 15 builds a program up from nothing and explains every line of it — the two sections, the registers with the dollar signs, and what a syscall actually is. This one is only a smoke test.

B.9Troubleshooting

Double-clicking the jar unpacks it into a folder of files, or does nothing at all.

The .jar extension is associated with an archiver (macOS Archive Utility, or WinRAR / 7-Zip on Windows) rather than with Java. A jar genuinely is a zip file, so the archiver is doing what it was asked — it was just asked the wrong thing.

Delete whatever folder it unpacked, keep the original jar, and start it with java -jar from a terminal instead (§B.4, §B.5). If you want double-clicking to work, fix the file association as described there.

"java: command not found", or Windows says 'java' is not recognized.

Java is either not installed or not on your PATH. Install the Temurin JDK from §B.2, then close and reopen the terminal — a window that was already open keeps the old environment and will keep saying this after a perfectly good installation.

On Windows, if it still fails after reopening, the installer's "Set JAVA_HOME" and "Add to PATH" options were probably left unticked. Run the installer again and tick them.

"UnsupportedClassVersionError", or "Unsupported class file major version".

The jar was built for a newer Java than the one running it. This is unusual with MARS, which asks for very little, so it normally means a genuinely ancient Java — check with java -version and install a current Temurin from adoptium.net.

If you have several versions installed, the one first on your PATH is the one being used, which may not be the one you just installed. Either reorder the PATH or give the full path to the java you want.

"no main manifest attribute in Mars.jar".

The file you downloaded is not the runnable jar — usually the source archive rather than the program. Go back to the download page in §B.3 and take the link that is plainly the program itself.

A half-finished download can produce the same message. Check the file size: the real jar is a few megabytes. A file of a few kilobytes is an error page your browser saved.

macOS says the file is damaged and should be moved to the Trash.

It is not damaged. macOS attaches a quarantine flag to anything downloaded from a browser, and for an unsigned jar it words the refusal unhelpfully. Remove the flag from a terminal, in the folder holding the file:

xattr -d com.apple.quarantine Mars.jar

Then start it with java -jar as usual. If xattr reports that there is no such attribute, the quarantine was not the problem — check your Java version instead.

MARS says it cannot find my file, or will not assemble it.

Three usual causes, in order of likelihood.

The file is not saved. MARS assembles what is on disk, not what is in the editor. An unsaved tab shows an asterisk or a modified marker in its title. Save first, then assemble.

The extension is wrong. It must be .asm. A text editor that helpfully added .txt gives you check.asm.txt, which MARS will not touch.

Assemble-all is on. If the error names a file you are not working on, turn off Assemble all files in directory in Settings (§B.7).

The program assembles and runs, but nothing is printed.

Look in the Run I/O box at the bottom of the Execute tab, not the Mars Messages box next to it. Messages carries the assembler's own output; Run I/O carries your program's.

If Run I/O really is empty, check that $v0 is loaded before the syscall that uses it. A syscall reads $v0 at the moment it executes, so the order of those two lines is the whole thing.

The program runs past the end and throws an error about an invalid instruction address.

It ran off the bottom of your code and kept going into whatever was next. Every program needs to stop itself explicitly:

li   $v0, 10
syscall

as its last two instructions. There is no implicit end — the processor has no idea your program is over.

A correct-looking program branches the wrong way, or executes one instruction too many.

Almost certainly delayed branching is switched on in Settings. With it on, the instruction after a branch runs even when the branch is taken, which is what real MIPS hardware does and is not what our lectures assume. Turn it off (§B.7) and reassemble.

The window is tiny, or the text is unreadable on a high-resolution screen.

MARS predates high-density displays and does not scale itself. Drag the window larger — it remembers the size — and set the font under Settings → Editor.

If the whole interface is still minuscule on Windows, right-click the Java executable (javaw.exe) → Properties → Compatibility → Change high DPI settings, and tick Override high DPI scaling behaviour, set to System.

My laptop will not let me install anything.

MARS does not need installing — it is one file that runs from wherever you put it, including a USB stick. The only thing that might need installing is Java, and the Temurin JDK can be unpacked into your own home folder without administrator rights.

If Java is blocked outright, come and see me; the lab machines have it.
