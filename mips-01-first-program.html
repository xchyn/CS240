A program changes machine state

MIPS assembly describes small operations on a machine: put a value in a register, add two values, read memory, or choose the next instruction. A useful question for every line is: What does it read, what does it change, and what executes next? A program's state includes its register values, memory contents, and current instruction.

The CPU contains registers and an arithmetic logic unit (ALU). RAM holds much more data than the registers can hold. In the ordinary MIPS load/store model, arithmetic uses register operands: load needed data, compute with registers, and store results when necessary. Intermediate results can remain in registers.

Registers: small named places for bits

There are 32 general-purpose registers, each holding 32 bits. Names such as $t0 are aliases for register numbers. Registers do not carry hidden labels saying “integer” or “address”; the instruction and program determine how the bits are interpreted.

NamesRole now
$zeroAlways reads as zero; writing it has no effect.
$t0–$t9Temporary working values.
$s0–$s7Values preserved across correctly written function calls.
$a0–$a3Arguments; today $a0 carries print arguments.
$v0–$v1Results; MARS also uses $v0 to select a service.

The $s naming convention does not make hardware save anything automatically. Functions will implement that agreement later. PC, HI, and LO are additional special state, not extra general-purpose registers.

A value and its address are different

Memory is byte-addressed: each address identifies one eight-bit byte. An address is the location of something; the value is the information stored there. A register can hold either. A string occupies several memory bytes, so its address fits in one register even when the entire string does not.

greeting: .asciiz "Hi"

This declaration stores the character codes for H and i, followed by a zero byte. The label greeting names the first byte's address. The terminating zero is not the character '0', whose ASCII code is 48. la $a0,greeting obtains the address; it does not copy the characters or print them.

The parts of an assembly source file

.data
greeting: .asciiz "Hello, MIPS!\n"
.text
.globl main
main:
    li $v0, 4
    la $a0, greeting
    syscall
    li $v0, 10
    syscall

.data selects declarations of stored data. .text selects executable instructions. .globl main makes the main label globally visible. Labels name locations; directives tell the assembler how to prepare the program. Neither is a runtime instruction.

li means load immediate: place a constant in a register. la means load address. These are assembler conveniences called pseudo-instructions; one source statement may expand into more than one basic machine instruction. The escape \n in the string represents a newline.

Assemble, run, and inspect in MARS

MARS is an assembler and simulator. The assembler translates source into encoded instructions; the simulator models their effects on a MIPS machine. Open L01_hello.asm and use Run → Assemble, then Step or Go.

For these lessons, enable extended/pseudo-instructions, disable delayed branching, and disable assembling all files in the directory. Each example is a separate program. Use the Text Segment for assembled instructions, Registers for values, Data Segment for memory, and Run I/O for input and output. Reset before repeating a trace, and assemble again after editing.

Changing hexadecimal to decimal display changes how a value is shown, not its stored bits. An assembly error occurs before execution; a runtime error occurs while executing an assembled program.

Worked example: Hello, MIPS!

The program above has five executable source statements. Trace their effects rather than reading them as English sentences:

  1. li $v0,4 selects the print-string service; it does not print the number 4.
  2. la $a0,greeting supplies the string's starting address.
  3. syscall asks MARS to perform the selected service. The greeting appears.
  4. li $v0,10 selects termination.
  5. The final syscall ends the program.

The string stays in memory while its address is passed in $a0. Printing does not remove its bytes. The prepared trace below follows source statements; a pseudo-instruction can correspond to multiple machine steps in MARS.

The four services needed today
MARS services use a register protocol: place the service number in $v0, place any argument in the specified register, execute syscall, and retrieve any result. These service numbers belong to the simulator environment, not to a universal MIPS operating-system interface.
$v0ActionArgument or result
1Print signed integer$a0 contains its value.
4Print string$a0 contains its address.
5Read integerThe entered value replaces $v0.
10ExitNo argument needed.
The same register can have different roles at different times. Immediately before service 5, $v0 contains 5. Immediately afterward, it contains the user's integer.

Worked example: read and echo an integer
li $v0, 5
syscall
move $t0, $v0
li $v0, 1
move $a0, $t0
syscall
For input −7, the first syscall leaves −7 in $v0. move copies that value to $t0 without erasing the source. Loading service number 1 then overwrites $v0, but the input survives in $t0. The second move supplies the integer argument, and the last syscall prints −7.
The complete echo program adds a prompt, output label, newline, and exit. Enter one valid signed 32-bit decimal integer. Test 7, 0, and −7. The input is a number, so service 1 expects the number itself, not its address.

What the machine sees
A basic instruction in this MIPS environment occupies 32 bits. The program counter (PC) identifies the current instruction address; straight-line execution normally advances to the next instruction. The assembler converts names and readable operations into instruction bits.
Compare the Source and Basic columns after assembling Hello World. A label is replaced by an address, and pseudo-instructions may expand. Therefore source-line counts are not reliable machine-instruction counts. In later lessons, branches and jumps will select a different next address.
Learn and work through
Inspect string bytes
Inspect the bytes associated with .asciiz "Hi". ASCII H is 72 decimal (0x48), i is 105 (0x69), and the terminator is 0x00. Three bytes are stored even though two visible letters print. Adding a newline before the terminator adds byte 0x0A.
Locate the label's address in MARS and compare it with $a0 after la. They should agree. Keep address and value displays separate: the address of H is not the ASCII value 72.
