Five parts of a counter loop

A loop repeats a block by returning to earlier code. A counter loop has five parts: initialization, test, body, update, and a jump back to the test. Initialization happens once. The test decides whether another body execution is allowed, and the update makes progress toward stopping.

Write the intended sequence of values before writing assembly. For for(i=0;i<n;i++), the body sees 0 through n−1. A backward jump alone does not guarantee useful repetition: without progress, the program can repeat the same state forever.

Worked example: sum the integers below n

Compute total=0; for(i=0;i<n;i++) total+=i;. Let $t0=n, $t1=i, $t2=total, and $t3=condition.

li $t1, 0
li $t2, 0
loop_test:
    slt $t3, $t1, $t0
    beq $t3, $zero, done
    nop
    add $t2, $t2, $t1
    addi $t1, $t1, 1
    j loop_test
    nop
done:

The test happens before the body. A zero flag exits; otherwise the current i is added, i advances, and execution returns to the test. Initialization is outside the repeated region so previous work is retained. The complete program accepts n in 0..1000 and prints the sum.

Worked example: 1² + 2² + … + n²
Now include n and start at 1. Stop when n<i, which is equivalent to continuing while i≤n.
li $t1, 1
li $t2, 0
loop_test:
    slt $t3, $t0, $t1
    bne $t3, $zero, done
    nop
    mult $t1, $t1
    mflo $t4
    add $t2, $t2, $t4
    addi $t1, $t1, 1
    j loop_test
    nop
done:
For n=3, the squares are 1,4,9 and the successive totals are 1,5,14. The next test has i=4 and exits. For n=0, the first test exits with total zero. In the complete program, n is restricted to 0..1000; the largest sum is 333833500 and fits signed 32 bits.
Do not assume that fitting individual squares imply a fitting sum. Both the product and the accumulated total need justified limits.

Learn and work through
Why the square-sum loop is correct
A loop invariant states what remains true whenever the loop reaches a particular point. At each test in the square-sum loop, total equals the sum of squares from 1 through i−1.
Initially i=1, so no integers have been processed and total=0 is correct. The body adds i², extending the completed range through i. Incrementing i restores the same statement for the next test. When the loop stops with i>n, total covers every requested integer.
The invariant explains the result; progress explains termination. Here i increases each time and the permitted n is finite. Both arguments matter.
Learn and work through
A sentinel loop gets progress from new input
A sentinel is a special input marking the end of data. In sentinel echo, −1 means stop. Each iteration prompts, reads a new value, compares it with −1, and echoes it only when it is not the sentinel.
# $t0 holds newly read input; $t1 holds -1
beq $t0, $t1, done
nop
# print the input
j read_next
nop
Inputs 5,0,−1 produce echoes for 5 and 0 only. Zero is ordinary data here. Entering −1 first gives no echo. The sentinel must be tested before processing.
Returning to the comparison without reading fresh input repeats the old value forever. In this algorithm, obtaining new input is the progress step; there is no counter update.

Worked example: divisible by 2 and 3, but not 4
For each i from 1 through N, test these requirements: i%2==0, i%3==0, and i%4!=0. Division puts the remainder in HI. Reject when either of the first two remainders is nonzero, or when the last remainder is zero.
Every rejection goes to a shared next_i label that increments i before returning to the loop test. Jumping straight to the test would skip the update and could trap execution on the same rejected value.
For N=31, 6 passes, 12 fails the “not 4” requirement, 18 passes, 24 fails, and 30 passes. The complete filter prints 6,18,30 on separate lines. It validates N in 1..2000.
For the OR variant, accept when any divisor 2,3,5 gives remainder zero. Join successful paths at one print block so a number satisfying multiple requirements prints only once.

Learn and work through
While versus do-while
A while loop tests before the first body execution. A do-while puts its body before the test and therefore executes at least once.
# do { i++; } while (i < 3);  i is $t0
body:
    addiu $t0, $t0, 1
    slti $t1, $t0, 3
    bne $t1, $zero, body
    nop
Starting at i=0 produces 1,2,3 and then stops. Starting at i=5 produces 6 and stops; the corresponding while loop would leave 5 unchanged because its first test fails. Use small starting values here so incrementing is within the signed range.
